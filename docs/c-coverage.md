# C11 coverage and `quant` data

The current goal is the [fully usable everyday C core](perfil-c-cotidiano.es.md), agreed on October
23, 2026. Functions, arrays, pointers, vectors and their common consuming contexts take priority.
The implementation has not completed that profile. [Version 1.0](v1-plan.md) remains a bounded
release milestone; the [complete inventory](c11-inventory.md) and [extended roadmap](c11-roadmap.md)
retain the broader C11 analysis without making every entry a completion requirement for this
profile. GCC parses C; the following table describes current capabilities. Recognizing a construct
does not imply implementing its quantum semantics.

Information-preserving operations may be synthesized coherently. Reading into CPU data requires
explicit measurement. A write that loses information must preserve it with defined ownership and
lifetime, or use an explicit program reset. Rejecting unimplemented cases protects these contracts
but does not count as functional support.

The [fourteen character adapters](c11-ctype.md) preserve input storage, raw classification masks,
EOF and effective global/thread locales through immutable profiles. They use interval-prefix
synthesis and support frozen profiles in unitary modules. Indirect calls, automatic per-capture
static locale traces, concurrency and complete pre-GCC source provenance remain P/R; invalid C
arguments have the standard undefined-domain contract.

The [controlled-operand contract](c11-controlled-operands.md) keeps supported pure CPU integer
calculations inside selected typed expressions for assignments, XOR, addition, integer absolutes and
byte fill. Reversible literal/scalar updates keep their in-place path. CPU loads through invalid
storage or invalid indices are skipped when saved symbolic certificates prove the coherent controls
inactive. Unknown controls remain possible and require valid CPU operands. General conditional
memory access is not implemented by this arithmetic correction; the
[current operand contract](c11-controlled-operands.md) records that later protection.

## Additional quantum transformations

The [memcmp adapter](c11-memcmp.md) reads checked integer object bytes reversibly, including
constant partial-element views, immutable constants and
[current CPU byte snapshots](c11-byte-snapshots.md) of known storage. Its integer result preserves
the first differing unsigned-byte sign. Direct zero comparisons use Boolean lexicographic circuits.
Unknown pointers, dynamic addresses/extents, volatile/atomic CPU accesses, general quantum layouts
and indirect quantum ABI remain pending. This extends read-only byte access, without implementing
general byte writes or libc.

The partial [`strlen`/`strcmp` adapters](c11-strings.md) preserve inputs and saved inverses on
checked integer object-byte views of at most 64 bytes. Dynamic pointers, extents, general layouts
and complete string-library compatibility remain pending.

`phase(theta)` accepts finite classical angles, constant or runtime-computed. Supported pure
binary32/binary64 arithmetic is deferred to the selected coherent domain, including typed integer
subexpressions. Checked pure CPU loads use a symbolic control query to skip proved-inactive arms
without measurement. General real calls, `long double`, quantum floating registers and complete
effect contracts remain pending. See the
[current evidence](audit-evidence/strings-integration-v6/README.es.md). `fourier` and
`inverse_fourier` transform an entire register, with or without coherent controls, using quadratic
synthesis. Neither enumerates the domain.

The examples `functions.c`, `vector_function.c`, `dynamic_vector.c`, `fourier.c`, and
`phase_estimation.c` exercise composition, borrows, CPU-indexed access, and interference algorithms.
`find_known` receives a count as a promise; `search` verifies candidates within bounded attempts,
including when no solutions exist. `find` promises one solution. None counts the domain beforehand;
predicates remain subject to synthesis limits.

## Evidence and progress criteria

The suite checks complete C programs, complex amplitudes, correlations, dependency versions,
cleanup, and invalid IR. Exhaustive tests enumerate specific domains: 256 inputs for eight-bit
arithmetic, 3720 adder pairs, 65,536 predicate inputs, and QFT bases from one to six bits. It also
includes 1024 seeded typed expressions compared with C over every input and inverted, plus 4096 IR
mutations exercising parsing and validation. This does not cover all of C11 or constitute a complete
fuzzing campaign.

`scripts/sanitize.sh` instruments tests and the engine. `scripts/sanitize-all.sh` also builds an
instrumented plugin, driver, backend, runtime, and generated executables in `build/sanitized`. Host
GCC is not instrumented; leak detection is disabled in its processes to avoid attributing
GCC-retained allocations to the plugin. ASan and UBSan remain active in the plugin; scalar checks
inserted by GCC before the quantum pass are replaced with quantum domain validation where
appropriate. CPU code checks remain.

Completing the language requires implementations and contract tests for the pending rows, alongside
broader synthesis. This table records that work without claiming complete C coverage.

Additional evidence includes amplitudes and inverses for eleven operators without tables, negative
operands and C rounding, 24 growth circuits up to 32 relevant bits, and generated frontend tests at
five optimization levels. The current C reference validator uses QuEST to check 70 exported QASM
circuits: 64 state cases and six sampled measurement/reset channels. Supplementary sparse-circuit
and labeled-basis audits use Python for selected full integer results beyond the dense simulator
limit. The README describes scripts and evidence. See [circuit-abi.md](circuit-abi.md) for the
circuit ABI.

The [strncmp adapter](c11-strncmp.md) adds bounded unsigned-character comparisons that stop at an
equal NUL. It preserves the inputs and the exact signed first-difference result, with direct Boolean
relations against zero. Checked ranges, pure helpers, readonly borrows and immutable constant
classical operands and current bytes of known CPU objects are partial support. CPU suffix loads are
disabled after that operand's own NUL; saved inverses retain the original captured bytes. Unknown
pointers, dynamic counts/addresses, volatile/atomic access and general string interfaces remain
pending. The [follow-up evidence](re-audit-2026-10-15-strings.md) separates complete states, saved
inverses, native execution and wide generation.
