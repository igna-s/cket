# Repository and paper re-audit, 2026-10-14/15

This report records the source states of the broad and numeric-locale campaigns below. The later
[memcmp adapter](c11-memcmp.md) advances the interface index separately; these older counts and logs
are preserved as historical evidence rather than relabeled for subsequent sources.

Full quantum C11/library compatibility remains incomplete. The interface index has 1224 entries
across 29 headers: 785 pending, 71 partial and 368 metadata-only. Inclusion of a header, successful
classical execution and a deliberate quantum rejection are different kinds of evidence.

Rebuilding the index from the official WG14 N1570 draft exposed fourteen stale `ctype` contracts in
the published JSON: they still described the previous fixed C-locale subset. The JSON now matches
the generator's immutable locale contract. A separate temporary rebuild reproduces all 1224 entries
and their contracts exactly. This validates index consistency for its declared target profile,
without converting the index into behavioral evidence.

## Reproduced backend bug

A second reproduction uses actual glibc `C` and `en_US.ISO-8859-1` classification profiles, rather
than the minimal profiles used for the fast regression matrix. Byte 192 is alphabetic in Latin-1 and
not in `C`: using the former classification as a guard cannot certify the latter as a nonzero
divisor. The [concrete IR](audit-evidence/profile-locale-division.json) and
[comparison log](audit-evidence/profile-locale-division.log) record acceptance with the pre-fix
comparison reconstructed by reverting its two added lines, and rejection with the corrected
comparison. Both profiles are acquired from native glibc over all byte values.

The arithmetic prover compared expression operators, integer types and operands but omitted the
immutable `ctype` profile. Two `ctype_isalpha(x)` nodes with disjoint profiles could therefore share
a branch fact. A condition that classified input zero as nonzero incorrectly certified a different
classification, which was zero on that input, as a valid divisor. The old backend accepted the
reachable division by zero with tables disabled and generated a circuit.

The equality check now includes decoded profile intervals and values. Whitespace differences do not
change equality; an omitted legacy profile can match its explicit interval representation.
Equivalent functions partitioned into different interval lists may conservatively compare unequal.

`tests/validate_profiles.c` checks 96 combinations of classifications and mappings, legacy and
explicit profiles, direct truth and comparison guards, both table policies, and simulation versus
export generation. Distinct contradictory profiles must be rejected. Accepted small domains are
checked against complete complex amplitudes before and after inverse/release, with no measurement or
reset. Linking the regression against the old backend reproduces the acceptance; the corrected
backend passes. Character expressions always require structured synthesis, so a conservative
rejection may report unavailable structured synthesis rather than a division-specific diagnostic.

## Additional library and frontend checks

Two direct IR probes confirmed that the reader accepts vertical tab and form feed as separators. The
IR contract now identifies this C-whitespace input extension explicitly; schema validation is
separate from strict JSON lexical conformance. The exporter emits ordinary JSON whitespace.

Locale-profile capture queries all 256 classical byte values and EOF for each of the fourteen
functions. The resulting immutable intervals parameterize the circuit. The table-free synthesis
claim concerns subsequent quantum expression synthesis, rather than the absence of bounded classical
profile acquisition; its CPU cost is outside logical gate counts. This distinction is now explicit
in the character-adapter contract.

`tests/validate_library.c` has 210 pending-interface fixtures, including floating and complex
families in all three C precisions, wide characters, memory/strings, allocation, locale, atomics,
I/O and selected environment effects. Every fixture must pass ordinary C syntax checks with warnings
treated as errors. Each then requires its declared quantum diagnostic at five GCC optimization
levels with builtins enabled and disabled: 2100 boundary checks. The shared runner rejects crashes,
timeouts and captured sanitizer faults as infrastructure failures.

These are negative compatibility tests. Positive adapters for absolute value, quotient/remainder,
memory copying and byte character profiles retain their separate native, complete-state, inverse,
composition and independent QuEST checks. No new general libc adapter is claimed by this matrix.

The frontend generator now compares each expression with C at every byte value, rather than seven
selected basis values. It preserves five optimization levels, reproducible seeds and the failing
source/log artifacts. Generated C has separate declarations and operations with consistent
indentation, making diagnostics and minimized reproductions easier to read. This basis-state
campaign does not replace tests of coherent phases, entanglement or uncomputation.

`python3 scripts/inventory_c11.py --require-complete` supplies a failing implementation-status gate
while the index contains pending or partial entries. Its normal mode validates the inventory without
claiming implementation completeness. Optional Python tooling is separate from the C test campaign.

## Numeric locales and final source state

A valid native program that selected `LC_NUMERIC=de_DE.UTF-8` failed at `phase(0.31)` with
`invalid finite numeric phase angle`: JSON numbers were converted with the caller's decimal locale.
Separately, preparing a circuit first and changing the numeric locale before C API export produced
`p(0,31) q[0];`, which is not the intended OpenQASM gate. The
[native failure](audit-evidence/numeric-locale-before.log) and
[old QASM output](audit-evidence/qasm-locale-before.log) preserve both reproductions.

Number conversion now uses an explicit immutable C numeric locale. QASM export temporarily selects C
numeric formatting for its thread, restoring the previous locale even after stream errors. No
process-wide locale is changed. The shared fixture helper supports named locales while preserving
the original Latin-1 fixture. Seventy checks cover four global/thread combinations, scalar numbers,
full phase/inverse states, controlled/global decimals, failed output streams and ten native C
programs at five optimization levels.

The complete broad campaign passed normally and with ASan/UBSan before this last correction: 391
native checks, 1452 example checks, 665 frontend compilations over every byte value, all specialized
arithmetic/history/locale suites, 2100 pending-library boundaries and 53 independent QuEST circuits
in each configuration. Its frozen source hashes and
[source capsule](audit-evidence/broad-source.tar.gz) identify those exact bytes.

The final numeric correction was tested on isolated source copies, then applied byte for byte. Its
normal and ASan/UBSan regressions repeat 391 native checks, 1452 example checks, 1815 character
checks, 96 profile proofs, the 70 new numeric checks and all 53 QuEST cases. The
[targeted report](audit-evidence/numeric-locale.json) records these source-copy identities, final
source hashes and the two separate logs. Copy hashes were captured after build start and compared
after testing/application; no pre-build frozen snapshot is claimed for that targeted run. The broad
transcript is not relabeled as a full rerun of the final amended tree. Future complete
`scripts/verify.sh` campaigns include the numeric regression in both configurations.

## Papers and physical scope

Both existing eight-page PDFs were rendered at 96 dpi and all sixteen pages were visually inspected
as four contact sheets. No layout defects were observed. The automated checks per language
separately cover text, figures, equations, counts, font/layout geometry and exact examples; they do
not certify every claim about the language or all external references.

The Spanish and English manuscripts describe the fixed historical revision
`1ebb2e308e61bed5632798ded5beecf77b6b9a9c`. Their 354 native tests, 426 example checks, 145 frontend
compilations, 24 synthesis circuits and 11 QuEST cases must not be relabeled as results for the
current working tree. The paper audit checks each language, figures, equations, resource CSV,
examples, PDF text and geometry; historical reproduction is a separate campaign. Its recorded source
hashes identify the audited working tree, not continuous observation during testing.

The isolated historical campaign was rebuilt and rerun, including a fresh build of its validation
tools. Sixty source files were compared byte for byte with Git at that revision. The rerun
reproduced 354 native tests, 426 example checks, 145 frontend compilations, 24 synthesis rows and 11
independent QuEST cases; all published synthesis CSV rows matched exactly. The
[rerun summary](audit-evidence/re-audit-baseline.json) records these counts. Current frontend tests
cover more basis inputs; this expansion is not attributed to the historical paper.

The public software link in reference [1], `https://github.com/igna-s/cket`, returned HTTP 404
without authentication on the audit date. No replacement public URL was available. Installation
instructions now start from an existing checkout and document this availability gap. The historical
paper citation is preserved. The Bennett DOI resolved to the publisher's robot check; its full text
was not independently inspected through that endpoint. Bibliographic links and automated PDF checks
alone are not evidence of public source-code availability or full-text verification.

The implementation synthesizes controlled X, H and phase operations. Measurement and reset are
explicit channels; copying basis values into fresh storage creates correlations and does not clone
an arbitrary state. The runtime executes a numerical state-vector simulation. This audit does not
establish execution on a physical QPU, hardware noise behavior, universal C11/library support or a
formal proof of absence of bugs. Numerical tolerances, synthesis budgets and the 24-qubit simulator
limit remain part of each result's scope.

Completed logs and reports live under `docs/audit-evidence/`; exploratory/interrupted transcripts
remain under `build/` and are not archived as complete campaigns. The broad and final targeted
reports deliberately identify different source states. The source capsule makes the broad state
reconstructable after the final correction.

The source snapshot now also includes JSON inputs, in particular `examples/increment.qir.json`.
Previously it hashed the C source that invoked this module but omitted the embedded circuit
artifact. Endpoint identity checks therefore covered only part of the example's source inputs. The
broad campaign was restarted after this snapshot correction; intermediate transcripts are not
archived as complete verification.

GCC's additional static analyzer produced no diagnostics for the JSON parser, simulator, driver,
backend, runtime and IR verifier. Analysis of the larger combined synthesis translation unit reached
a separate 90-second resource limit; it is not counted as a completed static analysis. Runtime tests
and sanitizers exercise that engine separately.

The extended sanitized validators previously resolved their compiler/backend relative to the
ordinary build directory. Their harnesses and linked reference libraries were instrumented, but the
frontend fuzzing, growth subprocesses and QASM exports still invoked the normal tools. They are now
staged beside the instrumented compiler/backend and run with the GCC wrapper; generated programs
link the instrumented runtime. Normal and sanitized growth CSVs must match. Sanitized frontend
failures are retained in the corresponding build tree and uploaded by CI. Earlier compiler/native
sanitizer checks remain distinct from this additional subprocess coverage.
